# Meal Planner 🥗

Вебдодаток для планування щотижневого харчування. Побудований за клієнт-серверною архітектурою з використанням **чистого Node.js** (без зовнішніх вебфреймворків) на бекенді та **Vanilla JS / HTML5 / CSS3** на фронтенді.

## 🚀 Запуск проєкту

### Вимоги:
* Встановлений [Node.js](https://nodejs.org/) (версія 18+).

### Команди для запуску:
1. Запуск сервера:

## 🔌 Документація REST API

Усі маршрути API розташовані за префіксом `/api`.

### 1. Рецепти (`/api/recipes`)
* **`GET /api/recipes`**
  * Повертає список рецептів.
  * Підтримує query-параметр пошуку: `?search=pasta`.
  * При першому запуску автоматично завантажує первинні дані з зовнішнього API DummyJSON.
  * Відповідь: `200 OK` `{ recipes: [...], total: number }`.
* **`POST /api/recipes/import`**
  * Примусове оновлення рецептів із зовнішнього джерела.
  * Відповідь: `201 Created` `{ message, imported, recipes }` або `502 Bad Gateway` при збої зовнішнього сервісу.

### 2. План харчування (`/api/plan`)
* **`GET /api/plan`**
  * Повертає заплановані страви.
  * Підтримує фільтри: `?day=monday` та `?search=soup`.
  * Відповідь: `200 OK` `[ { id, name, day, mealType, time, ... } ]`.
* **`POST /api/plan`**
  * Додає нову страву до плану.
  * Тіло запиту (JSON):
    ```json
    {
      "name": "Вівсянка з ягодами",
      "day": "monday",
      "mealType": "breakfast",
      "time": 15,
      "recipeId": 1
    }
    ```
  * Відповідь: `201 Created` з об'єктом створеної страви, або `400 Bad Request` при помилці валідації.
* **`PUT /api/plan/:id`**
  * Оновлює параметри страви (день, прийом їжі, назву, час).
  * Тіло запиту (JSON):
    ```json
    {
      "day": "tuesday",
      "mealType": "lunch"
    }
    ```
  * Відповідь: `200 OK`, `400 Bad Request` або `404 Not Found`.
* **`DELETE /api/plan/:id`**
  * Видаляє страву з плану за її ідентифікатором.
  * Відповідь: `200 OK` `{ success: true, deleted }` або `404 Not Found`.

### 3. Статистика (`/api/stats`)
* **`GET /api/stats`**
  * Повертає кількість страв та середній час приготування.
  * Відповідь: `200 OK` `{ totalMeals: number, averageTime: number }`.

## 🛡️ Стандарти HTTP-статусів

* **`200 OK`** — успішне виконання запиту на читання, оновлення чи видалення.
* **`201 Created`** — успішне створення нового запису (`POST /api/plan`, `POST /api/recipes/import`).
* **`400 Bad Request`** — помилка валідації вхідних даних або некоректний JSON.
* **`404 Not Found`** — запис за ID не знайдено або невідомий URL.
* **`500 Internal Server Error`** — внутрішній неочікуваний збій сервера.
* **`502 Bad Gateway`** — помилка при зверненні до зовнішнього API рецептів.

## ✨ Особливості інтерфейсу

1. **Дворівнева перевірка даних**: миттєва валідація на frontend + суворий захист на backend.
2. **Захист від дублювання**: блокування кнопок під час виконання мережевих запитів.
3. **Статуси завантаження**: показ `Loading...` та спінерів при асинхронних операціях.
4. **Toast-повідомлення**: спливаючі повідомлення про успіх (зелені) та помилки (червоні).
5. **Підтвердження видалення**: стильне модальне вікно для запобігання випадковому видаленню.
6. **Інформативні порожні стани**: показ підказок, якщо список рецептів або плану порожній.
